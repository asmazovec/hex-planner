# Тесты правил

Каталог `src/domain/rules/lrr/`: **один номерной раздел Rules Reference = один файл** (`001-abilities.test.ts` … `101-wormholes.test.ts`) и 8 разделов Thunder's Edge без номеров (`te-*.test.ts`). В каждом файле по порядку перечислены все подпункты раздела и примечания (официальные разъяснения из раздела Notes):

- `test(...)` — пункт, который приложение моделирует хотя бы частично (расчётом, предупреждением или кодом UI);
- `test.todo('… — not modelled: причина')` — пункт, который приложение сознательно не моделирует (бой и броски, карты действий, цели, политика, сделки, лидеры и т. п.). Он виден в выводе Vitest, поэтому пропуск не может быть молчаливым.

Источник: `ti4/tirules2/rules-reference/<раздел>.md` из базы RAG. Тесты пересказывают правило, без цитат. Доска: `src/domain/rules/kit.ts`, помощники 83-101: `lrr/kit-83-101.ts`. Коды предупреждений сравниваются как строки, поэтому тест может назвать код, которого в `WarningCode` ещё нет, и сборка не ломается.

Запуск: `npx vitest run src/domain/rules`.

## Решения перед Фазой 2

Ошибки B1–B20 исправляют то, что приложение уже моделирует, — их предлагаю чинить все. Группы «нет предупреждения» и «не хватает данных» вводят новые предупреждения и данные, а CLAUDE.md требует лёгкости. По каждой группе решите, нужна ли она: ненужную удалю вместе с тестами (в `todo` с причиной «отклонено пользователем»), а не стану реализовывать.
