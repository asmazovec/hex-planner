## Команды

- Разработка: `npm run dev`
- Сборка (проверка типов и Vite): `npm run build`
- Линт: `npm run lint`
- Термины игры: `npm run lint:terms` (Vale, стили в `.vale/styles`: `TI4` по английскому Rules Reference, `TI4Ru` по русскому Hobby World и правилам ниже)

- Все тесты: `npm test` (то же, что `npx vitest run`)
- Один тест: `npx vitest run src/ui/App.test.tsx` (или `npx vitest run -t "часть названия"`)
- Сквозные тесты: `npm run e2e` (Playwright, установленный Chrome, 1180×820). Сам собирает приложение и запускает `vite preview` на порту 5301: у каждого порта своя база браузера, партии на 5199 не затрагиваются. Сервис-воркер есть только в сборке, не в `npm run dev`.
- Публикация на планшет: `npm run deploy`. Собирает приложение и принудительно отправляет только сборку в ветку `gh-pages` репозитория из git remote `pages` (GitHub Pages, сайт открытый). Исходники лежат в `main` того же репозитория, код под лицензией MIT.

Полный дизайн: [docs/superpowers/specs/2026-11-05-ti4-planner-design.md](docs/superpowers/specs/2026-11-05-ti4-planner-design.md). Сверка игровых данных с источниками: [docs/data-verification.md](docs/data-verification.md).

## Продукт

Лёгкий планировщик партии в Twilight Imperium 4 на веб-технологиях, локальное PWA с упором на планшет в альбомной ориентации. Игрок вручную строит план по раундам, а приложение считает ресурсы, жетоны и лимиты.

**Главное требование: инструмент должен оставаться лёгким.** Пользователь уже отклонил ветки планов, таблицы сравнения и автоматизацию правил как избыточные. Новые функции предлагай в самом простом виде и не добавляй сложность без запроса.

## Архитектура

Зависимости идут в одну сторону:

- `scripts/`: сборщик игровых данных и картинок юнитов, генератор иконок приложения и их тесты; в приложение не входит.
- `src/data`: загрузка пакетов и пересказы карт.
- `src/domain`: чистый TypeScript без React и браузерных API, включая единый расчёт состояния. Правила, которые нужны экрану, тоже здесь, а не в `src/ui`: запись тактического действия (`tactical.ts`), тела новых записей (`newEntry.ts`), кто где стоит на тайле и в большом гексе (`stacks.ts`), движение (`movement.ts`).
- `src/state`, `src/storage`: хранилище партии, IndexedDB, экспорт и импорт файла.
- `src/ui`: экраны, карта, жесты на pointer-событиях. Тексты в `src/i18n`.

Состояние партии не хранится, а всегда вычисляется повторением записей плана. «Сейчас» считается только по выполненным записям, «прогноз» по выполненным и запланированным. Каждый план на вкладке хранит собственную копию записей.

Повтор лежит в `src/domain/replay/`: раунды по фазам, запись по шагам, один модуль на шаг (`activation`, `movement`, `transport`, `combat`, `invasion`, `production`, `payment`, `status`, `round`, `expedition`, `structures`). Каждая карта стратегии отдельным файлом в `src/domain/replay/cards/` (контракт в `handler.ts`): цена, жетоны, эффекты и проверки; редактор зовёт те же функции. `src/domain/project.ts` только реэкспортирует, приложение импортирует оттуда.

Папки `src/ui`:

- `primitives/`: общие мелкие элементы (`Section`, `SectionTitle`, `PlayerDot`, `PlayerChoice`, `ConfirmBar`, `MapPickButton`, `Stepper`, `HexRemove`).
- `feedback/`: предупреждения (`WarningText`, `WarningList`, `warningPlaces.ts`) и `Banner`.
- `overlays/`: `Modal`, `Drawer`, `DrawerSheet`, `DrawerTab`, `Popover`.
- `drawers/`: содержимое шторок.
- `plan/editors/`: редакторы записей, у карт стратегии свои блоки в `plan/editors/cards/`; `plan/blocks/`: блоки редакторов (высадка, оплата, жетоны, сетка карт).
- `map/stage/`: большой гекс и магазин; `map/builder/`: сборка карты.
- `screens/plan/`: состояние экрана плана, один выбор на карте на весь экран (`pick.ts`).

Общие контейнеры и есть визуальный язык: новый интерфейс собирается из `Section`, `SectionTitle`, `PlayerDot`/`PlayerChoice`, `UnitTile`, `ConfirmBar`, `Modal`, `DrawerSheet`, `Popover`, `MapPickButton`, а не из своей разметки и стилей.

## Интерфейс

- Меню из двух экранов, «Партия» и «План и карта», гексами в колонке слева, внизу кнопка экспорта; пока партия не создана, меню нет. Игроки, дополнения и язык живут на «Партии». План и карта на одном экране.
- Карта собирается на «Партии», в блоке «Карта и места» рядом с игроками: мини-карта показывает номер каждой клетки, Mecatol, домашние системы и гиперпути шаблона ставятся сами, нажатие на свободную клетку открывает ввод номера (страница при этом не прокручивается), «Вставить строку Milty» заполняет всё. После старта номера тайлов меняются, раскладка и места нет. На «Плане и карте» инструментов сборки нет; недостроенная карта даёт подсказку с кнопкой «Достроить карту».
- Нажатие на систему открывает большой гекс (сцену) с режимами «Расстановка», «Бой», «Строительство» и «Контроль» (свойства тайла и контроль планет, только чтение тайла). Fracture ставится по номеру места игрока.
- Игроки, легенда, улучшения и Thunder's Edge выезжают из вертикальных шторок по бокам карты, без кнопок закрытия. Левые размывают фон и закрываются нажатием вне себя. Правые выезжают из-под панели плана, не мешают карте и закрываются только повторным нажатием на язычок. Карта лежит в глубине: тень по всему её краю, шторка отбрасывает на неё свою, между шторкой и планом тени нет. Над картой висят только действия с ней, «прогноз/сейчас» стоит справа от раундов. Крестик везде один: `HexRemove`.
- Предупреждение стоит в том блоке, где настраивается то, о чём оно говорит: маршрут, высадка, постройка, оплата, жетоны, карта. Блок выбирается по шагу предупреждения (`STEP_PLACES` в `src/ui/feedback/warningPlaces.ts`), поэтому новому правилу правка там не нужна; `PLACES` хранит только исключения, когда один шаг говорит о нескольких блоках. Блок показывает их через `WarningList` с оранжевым краем. Предупреждение, чей блок не на экране, стоит вверху редактора, чтобы не потеряться. Лимиты системы (флот, места на борту) считаются по всему действию и стоят в блоке «Итог действия» в конце тактического редактора, а если есть источники, то и в них.
- Бой тактического действия: строка `.in-card` в редакторе с итогом внутри (как и «Производство»), потери `entry.losses` накликиваются иконками, снимаются после перелёта и до высадки и производства, поэтому влияют на резерв флота и на то, что можно высадить. Юнит из десанта этого действия, потерянный в бою, уходит из `landings` и считается в `losses`; потери тех, кто уже стоял на планете, идут в `groundLosses` и снимаются после высадки. Блок высадки показывает всё после боя. Потери других игроков в действие не входят.
- Маршрут строится одним черновиком: выбор источника только начинает его, а нажатия и штрихи пальцем чередуются в любом порядке. В запись он попадает на активной системе. Пока он строится, подсказка показывает скорость самого быстрого корабля источника, а подсветка показывает, куда ещё можно долететь. Счёт в `src/domain/movement.ts`: червоточины смежны, дом вне карты (Creuss) смежен только через свою червоточину, гиперпуть соединяет системы только по своим линиям с учётом поворота (у тайлов без данных о линиях, 119-124, соединены все стороны). В астероиды и сверхновую нельзя; в туманность и к чужим кораблям только как в активную систему, и не насквозь; старт из туманности даёт скорость 1; каждый гравитационный разлом даёт +1 за каждый выход или пролёт; две отмеченные подряд несоседние системы (нет общей стороны, червоточины или линии гиперпути) — прыжок: Излом, портал или способность, которую правила здесь не считают; он рисуется пунктиром, стоит один шаг, и системы между ними не проверяются; маршрут можно вывести из активной системы и вернуть в неё; энтропийный шрам на движение не влияет. Технологии не учитываются. Подсветка и предупреждения `speedShort`, `routeBlocked` ничего не запрещают.
- Элемент управления карточкой (удаление и подобное) стоит внутри карточки, у её правого края, а не сбоку и не вплотную к тексту: класс `.in-card` для кнопки-карточки, как строка источника; строки вроде сохранённых партий и записей плана сами являются карточкой, текст в них занимает свободное место.
- Карта стратегии в сетке: под сеткой показаны свойства основной карты. Первое нажатие на любую карту, и на свою тоже, только открывает её справку; следующие нажатия на неё делают её запасной (при 3-4 игроках второй), основной, снимают выбор. Нажатие вне блока стратегий закрывает справку, возвращает основную карту и начинает счёт заново.
- В режиме «Факт» итоги сверху показывают только то, что есть, без стрелок «А → Б».
- Цвет состояния, три вида: не выбрано без подсветки (край нейтральный); выбрано голубым везде, в том числе вкладки плана, язычки и край открытой шторки, текущий экран меню, лист фракций, действия над картой; зелёный только у выполненного действия (галочка записи и край строки). Золотой только для значений: ресурсы, изменённое число, «пора сделать копию».
- Удалить, изменить, выполнено: тихий значок `.icon-button` (знак 24 px без рамки в поле 44×44). Нажатое или выполненное рисуется шестиугольником за значком без края, с радиальной заливкой, тающей к краям; крестик краснеет только под пальцем или курсором. Шестиугольники меню и действий над картой остаются `.hex-button`.
- Модалы на весь экран размывают фон, это выключается на «Партии» (`localStorage`, `ti4.blur`).
- Блок «Энергосбережение» на «Партии» (`src/ui/screens/EnergySettings.tsx`, `src/ui/common/preferences.ts`): пункты «Перелёты кораблей» (`ti4.flights`, `data-flights`), «Повтор перелётов» (`ti4.flightLoop`), «Плавная анимация» (`ti4.motion`, `data-motion`), «Размытие фона» (`ti4.blur`, `data-blur`) включены по умолчанию и выключаются по одному. «Максимальная экономия» (`ti4.energy`, по умолчанию выключена) стоит в том же ряду: пока она включена, все пункты выключены и заблокированы, их собственный выбор сохраняется и возвращается после неё. На корне всегда то, что действует сейчас (`applyAll`). Код читает анимацию через `reducedMotion()`, перелёты через `playsFlights()`, обе вместе с системной настройкой.
- Повтор перелёта идёт фазами (`useFlightLoop`, `FlightLayer`): откат к состоянию до действия (с жетоном приказа уже на месте), стоянка, взлёт (юниты уходят из систем, строй вырастает в начале маршрута), полёт с подборами (подобранный стек вырастает в строю), долёт до центра целевой системы, высадка (строй тает, юниты появляются). Анимируются только системы действия (`entrySystems`): их планеты, юниты и метки рисуются порталом в слой `hexmap-lift` поверх карты, остальные тайлы получают `tile-quiet` и меняются мгновенно. Смена числа у стека — это уход старого значка и появление нового (`TokenLayer`). Летящие юниты рисуются в своём слое `hexmap-overlay` поверх карты. Кадры жеста и подлёта камеры пишут трансформацию прямо в DOM (`onFrame` в `usePanZoom`), React узнаёт вид только в конце.
- Перелёт в открытых деталях повторяется, только если ему есть что показать (`flies`). Между повторами карта стоит в состоянии сразу после действия (`stateAfterEntry`), чтобы последующие записи плана не мигали.
- Кнопка экспорта с иконкой (`ExportReminder`) стоит внизу колонки меню и просит постоянное хранение; когда нужна новая копия, она отмечена золотым. Время последней файловой копии лежит в `localStorage` (`ti4.lastExportAt`). Отметка появляется, если копии не было никогда, если она старше недели при постоянном хранении или старше суток без него. Экспорт её снимает.

- Битое сохранение ничего не ломает: оно стоит в списке с сообщением «Сохранение не удалось загрузить», его можно выгрузить как есть или удалить с подтверждением, само оно не удаляется никогда; падение отрисовки открытой партии возвращает на «Партию» с тем же сообщением (`src/storage/db.ts`, `src/ui/common/ErrorBoundary.tsx`).

## Ссылка на партию

Query-параметры (`src/domain/shareLink.ts`): `name` (имя сохранения), `map` (строка Milty), `factions` по местам с первого, коротким кодом из трёх hex-цифр (`factionCode`, хеш id; `-` значит пусто, старые ссылки с id тоже читаются), `me` (своё место), `exp` (`pok,te`, `base` значит без дополнений), `layout`. При запуске: сохранения с таким именем нет, партия создаётся и открывается (без своей фракции ждёт в черновике); есть и не расходится со ссылкой, открывается; расходится, окно `ShareConflict` предлагает новую партию под другим именем или игнорировать ссылку. Сохранение ссылка не меняет никогда, то, что она не упоминает, расхождением не считается. Без `name` ссылка только заполняет черновик. Пока партия открыта, адрес всегда содержит её параметры (`App`, без записей в истории), поэтому его можно просто скопировать; без открытой партии адрес чистый. Планы в ссылку не входят; кнопка «Скопировать ссылку» на «Партии» собирает её.

## Действия соперников

В план можно внести ожидаемое действие соперника: у записи есть `owner`. Соперник считается тем же кодом, что и я: `gameAs` показывает партию его глазами, а `state.rivals[id]` хранит его состояние, начиная с того, что стоит на карте. Редакторы и большой гекс получают `gameAs`, стрелки и жетоны окрашены цветом игрока. Номер тактического действия значит круг этого игрока: у каждого счёт свой, с единицы. Строка соперника сдвинута вправо и с оттенком его цвета, а левая граница у неё значит то же, что у моих: выполнено или предупреждение. На мои итоги действия соперника не влияют, кроме контроля планеты при его высадке. После старта партии нельзя менять имя, добавлять соперников и пересаживать игроков. При старте партии `placeStartUnits` ставит стартовые юниты соперников на их места.

## Правила домена

- Предупреждения ничего не запрещают: способности и технологии могут менять правила. Способности и карты учитываются ручными правками с подписью.
- Канал нарушений один. Предупреждение (`Warning`) создаёт только домен, через `violation` из `src/domain/rules/registry.ts`; оно несёт правило (`rule`), шаг (`step`) и место (`place`: запись, источник, планета). Реестр `RULES` даёт каждому коду пункты LRR и шаг, на котором он проверяется. Новый код: `WARNING_CODES` в `types.ts`, запись в `RULES`, тексты ru и en, тест правила. Контрактные тесты `src/domain/rules/contract.test.ts` требуют, чтобы каждый код был в реестре и в тесте правила, у каждого шага был блок, а `src/ui` предупреждений не создавал.
- Стратегия в меню одна: сначала карта (по умолчанию моя ещё не сыгранная в этом раунде, иначе никакой), затем её основная или второстепенная способность. Основная бесплатна на моей карте и стоит жетон на чужой. `forToken` выводится из карт раунда (`primaryForToken`): пока карта раунда выбрана, решает она, флаг записи учитывается, только когда карт нет; `withForTokenOfRound` подгоняет сохранённые записи. Мои карты зависят от числа игроков (`heldCards`): при 5 и больше только основная. Повтор своей карты за раунд предупреждает (`primaryRepeated`). Второстепенная стоит жетон, кроме Leadership. Карты соперников не планируются, поэтому их основная бесплатна.
- Здания принадлежат тому, кто контролирует планету: состояние игрока хранит только свои, а захват планеты другим игроком их уничтожает (`src/domain/replay/structures.ts`).
- Дополнения выбираются независимо: Thunder's Edge требует базовую игру, но не Prophecy of Kings.
- Раскладки карты по правилам PoK, у каждого числа игроков две (`LAYOUT_CHOICES` в `src/domain/layouts.ts`): на 3-5 обычная и с гиперпутями (на 3 и 4 гиперпути Milty), на 6 обычная и Большая галактика, на 7 с гиперпутями и альтернативные гиперпути, на 8 обычная и альтернативные. По умолчанию раскладка правил: гиперпути на 5 и 7. Шаблоны 6-8 игроков переписаны вручную с диаграмм правил (`RULEBOOK_LAYOUTS` в `scripts/build-data.ts`); смена раскладки переносит дома на места новой. Карты на 7 без гиперпутей в правилах нет, схема 5 переносит такие сохранения.
- Набор стратегических карт зависит от дополнений. Thunder's Edge заменяет Construction и Warfare.
- Стрелки на карте используются только для перемещения в тактическом действии.
- Лидеры и мехи существуют только с Prophecy of Kings, даже у фракций Thunder's Edge (правила TE). Thunder's Edge заменяет часть карт: у Jol-Nar Ta Zern на Agnlan Oln; что на что, задано в `scripts/build-data.ts`. Каждый такой компонент подписан дополнением.
- Системы открытого Излома лежат в `game.fracture.tiles` под обычными ключами слотов, поэтому ходы, расчёт и большой гекс работают с ними как с картой. Они не смежны с тайлами карты рядом: такой шаг маршрута рисуется разрывом.

## Данные и язык

- Игровые данные берутся только из публичных источников и хранятся как пакеты с указанием происхождения. Источники и правила сборки описаны в спецификации.
- Числа из прототипов частично заполнены по памяти, не переноси их в приложение.
- Не копируй арт из игры и источников: лицензия AsyncTI4 его исключает, а у KeeganW/ti4 лицензии нет. Описания карт пересказывай своими словами.
- Интерфейс идёт через i18n: русский и английский, с выбором языка. Игровые названия остаются на английском. Термины игры берутся из официальных правил: английские по Rules Reference, русские по Hobby World (жетон приказа, тактический и стратегический резерв, резерв флота, база, наземные войска, второстепенная способность, места на борту, значение полёта); следит `npm run lint:terms`. Если полный термин не помещается в кнопку, перестрой фразу, а не сокращай термин. Исключение: commodities по-русски «Продукция», trade goods «товары».
