# CLAUDE.md

## Команды

- Разработка: `npm run dev`
- Сборка (проверка типов и Vite): `npm run build`
- Линт: `npm run lint`
- Термины игры: `npm run lint:terms` (Vale, стили в `.vale/styles`: `TI4` по английскому Rules Reference, `TI4Ru` по русскому Hobby World и правилам ниже)
- Тесты правил 1 к 1 с Rules Reference: `npx vitest run src/domain/rules`. В `src/domain/rules/lrr` один файл на раздел LRR (`095-transport.test.ts`), название теста начинается с номера пункта; доска для них в `src/domain/rules/kit.ts`. Не смоделированный пункт пишется как `test.todo` с причиной.
- Партии компонентов для работы над эффектами: `npm run plan:effects` (scripts/effect-batches.ts, результат docs/phase4/batches; `-- --status` показывает, что уже написано). Руководство по эффектам: [docs/phase4/component-effects.md](docs/phase4/component-effects.md).
- План Фазы 2 из комментариев `TODO(P2-…)`: `npm run plan:todos` (формат в docs/phase2/todo-format.md, потоки в scripts/todo-plan.workstreams.ts, результат docs/phase2/plan.md)
- Все тесты: `npm test` (то же, что `npx vitest run`)
- Один тест: `npx vitest run src/ui/App.test.tsx` (или `npx vitest run -t "часть названия"`)
- Сквозные тесты: `npm run e2e` (Playwright, установленный Chrome, 1180×820). Сам собирает приложение и запускает `vite preview` на порту 5301: у каждого порта своя база браузера, партии на 5199 не затрагиваются. Сервис-воркер есть только в сборке, не в `npm run dev`.
- Публикация на планшет идёт сама: каждый push в `main` репозитория из git remote `pages` проверяется (линт, тесты), собирается и публикуется GitHub Actions (`.github/workflows/pages.yml`) в ветку `gh-pages`, которую отдаёт GitHub Pages (сайт открытый). В ветке только сборка, без истории. `npm run deploy` делает то же с этой машины, минуя `main`: запасной путь. Код под лицензией MIT.

В `src/test-setup.ts` подменяется `localStorage`: глобальный `localStorage` в Node 25 затеняет jsdom и без флага не работает.

Полный дизайн: [docs/superpowers/specs/2026-11-05-ti4-planner-design.md](docs/superpowers/specs/2026-11-05-ti4-planner-design.md). Сверка игровых данных с источниками: [docs/data-verification.md](docs/data-verification.md).

## Продукт

Лёгкий планировщик партии в Twilight Imperium 4 на веб-технологиях, локальное PWA с упором на планшет в альбомной ориентации. Игрок вручную строит план по раундам, а приложение считает ресурсы, жетоны и лимиты, знает каждый компонент игры, у кого он, и само применяет его эффект там, где это возможно. Дизайн учёта компонентов: [docs/superpowers/specs/2026-11-10-components-design.md](docs/superpowers/specs/2026-11-10-components-design.md).

**Главное требование: инструмент должен оставаться лёгким.** Пользователь уже отклонил ветки планов, таблицы сравнения и симуляцию боя как избыточные; автоматическое применение способностей, карт и технологий в продукт входит (решение от 2026-11-10). Новые функции предлагай в самом простом виде и не добавляй сложность без запроса.

## Архитектура

Зависимости идут в одну сторону:

- `scripts/`: сборщик игровых данных и картинок юнитов, генератор иконок приложения и их тесты; в приложение не входит.
- `src/data`: загрузка пакетов; дословные тексты компонентов лежат отдельно в `src/data/texts` (принадлежат издателю, см. `NOTICE.md` там).
- `src/domain`: чистый TypeScript без React и браузерных API, включая единый расчёт состояния. Правила, которые нужны экрану, тоже здесь, а не в `src/ui`: запись тактического действия (`tactical.ts`), тела новых записей (`newEntry.ts`), кто где стоит на тайле и в большом гексе (`stacks.ts`), движение (`movement.ts`).
- `src/state`, `src/storage`: хранилище партии, IndexedDB, экспорт и импорт файла.
- `src/ui`: экраны, карта, жесты на pointer-событиях. Тексты в `src/i18n`.

Состояние партии не хранится, а всегда вычисляется повторением записей плана. «Сейчас» считается только по выполненным записям, «прогноз» по выполненным и запланированным. Каждый план на вкладке хранит собственную копию записей.

Повтор лежит в `src/domain/replay/`: раунды по фазам, запись по шагам, один модуль на шаг (`activation`, `movement`, `transport`, `combat`, `invasion`, `production`, `payment`, `status`, `round`, `expedition`, `structures`). Каждая карта стратегии отдельным файлом в `src/domain/replay/cards/` (контракт в `handler.ts`): цена, жетоны, эффекты и проверки; редактор зовёт те же функции. `src/domain/project.ts` только реэкспортирует, приложение импортирует оттуда.

Папки `src/ui`:

- `primitives/`: общие мелкие элементы (`Section`, `SectionTitle`, `PlayerDot`, `PlayerChoice`, `ConfirmBar`, `MapPickButton`, `Stepper`, `HexRemove`).
- `feedback/`: предупреждения (`WarningText`, `WarningList`, `warningPlaces.ts`) и `Banner`.
- `overlays/`: `Modal`, `Drawer`, `DrawerSheet`, `DrawerTab`, `Popover`.
- `drawers/`: содержимое шторок.
- `plan/editors/`: редакторы записей, у карт стратегии свои блоки в `plan/editors/cards/`; `plan/blocks/`: блоки редакторов (высадка, оплата, жетоны, сетка карт).
- `map/stage/`: большой гекс и магазин; `map/builder/`: сборка карты.
- `screens/plan/`: состояние экрана плана, один выбор на карте на весь экран (`pick.ts`).

Общие контейнеры и есть визуальный язык: новый интерфейс собирается из `Section`, `SectionTitle`, `PlayerDot`/`PlayerChoice`, `UnitTile`, `ConfirmBar`, `Modal`, `DrawerSheet`, `Popover`, `MapPickButton`, а не из своей разметки и стилей. Набор юнитов из запаса (корабли и груз полёта, высадка, покупка и постройка, снятие сверх резерва флота) — только `UnitDraft` (`src/ui/units/UnitDraft.tsx`): строка на место, кнопки «взять» с остатком, лоток набранного с постоянным местом на каждый тип; остаток считает вызывающий код; раскладок две, проп `layout` (у строки можно свой): `horizontal` (по умолчанию) — место, кнопки и лоток в одну линию, `vertical` — место отдельной строкой, под ним кнопки, под ними лоток в тех же колонках (тип и его место в лотке стоят друг над другом); в узких панелях (план, большой гекс) строку с тремя и больше типами ставит вертикально `layoutFor`, корабли в космосе вертикальны всегда; что драфт нигде не вылезает из панели и не переносится вразнобой, следит `tests/e2e/unit-draft.spec.ts`; пустой запас ничего не запрещает: кнопка во всех строках меняет вид на «сверх запаса» (пунктир, приглушённая картинка, оранжевые «+» и число взятого сверх), остаётся нажимаемой, а о нарушении говорит предупреждение домена в блоке шага. `disabled` только по собственной причине (`blockedReason`: вторая база на планете, корабля в системе уже нет). Планета рядом с выбором — `PlanetBadge` (`src/ui/map/PlanetBadge.tsx`), космос системы — `SpaceBadge`.

## Интерфейс

- Меню из двух экранов, «Партия» и «План и карта», гексами в колонке слева, внизу кнопка экспорта; пока партия не создана, меню нет. Игроки, дополнения и язык живут на «Партии». План и карта на одном экране.
- Карта собирается на «Партии», в блоке «Карта и места» рядом с игроками: мини-карта показывает номер каждой клетки, Mecatol, домашние системы и гиперпути шаблона ставятся сами, нажатие на свободную клетку открывает ввод номера (страница при этом не прокручивается), «Вставить строку Milty» заполняет всё. После старта номера тайлов меняются, раскладка и места нет. На «Плане и карте» инструментов сборки нет; недостроенная карта даёт подсказку с кнопкой «Достроить карту».
- Нажатие на систему открывает большой гекс (сцену; гекс 490 px, панель справа 410 px, чтобы семь типов кораблей магазина стояли в одну линию) с режимами «Расстановка», «Бой», «Строительство» и «Контроль» (свойства тайла и контроль планет, только чтение тайла). Fracture ставится по номеру места игрока.
- Игроки, легенда, компоненты и Thunder's Edge выезжают из вертикальных шторок по бокам карты, без кнопок закрытия. Левые размывают фон и закрываются нажатием вне себя. Правые выезжают из-под панели плана, закрываются повторным нажатием на язычок и сами, когда начинается выбор на карте (`closeRight` в `useDrawers`). Язычок «Компоненты» в свёрнутом виде — стопка: верхний язычок над тенями остальных; нажатие раскрывает её веером по группам (`ComponentTabs`: «Технологии», «Карты», «Фракция», «Реликвии», «Цели и законы», с числом компонентов показанного игрока), язычок Thunder's Edge на это время уходит. Веер выезжает вместе с листом компонентов и висит на его внешнем краю, со стороны карты, как язычок любой шторки (рельс получает `drawer-rail-open`). Открытая группа встаёт первой, на высоте стопки, и повторное нажатие на неё сворачивает веер (точек у пальца две и они постоянны: стопка у края карты открывает, первый язычок на краю листа закрывает); остальные идут в обычном порядке и, пока веер раскрыт, не двигаются: смена группы не сдвигает ни одного язычка. Последняя группа лежит в `localStorage` (`ti4.componentsTab`). Карточка компонента (`ComponentCard`) — одна рамка: шапка с названием и подробности (текст карты) внутри неё, свёрнутые, раскрываются нажатием на шапку вниз, шапка при этом не двигается; технология говорит свой тип значком у названия (`TechMark` цвета типа, «II» у улучшения юнита), поэтому «Изученные технологии» — один список без заголовков по типам, по типам в порядке колоды, внутри типа в порядке изучения. Группа «Карты» начинается с блока «Мои обязательства»: все обязательства показанного игрока, каждое с тем, где оно сейчас (на руке, у какого игрока, вне игры; `ownNotes` в `src/domain/holdings.ts`), ниже «Чужие обязательства», которые он держит, и карты действий. Карта лежит в глубине: тень по всему её краю, шторка отбрасывает на неё свою, между шторкой и планом тени нет. Над картой висят только действия с ней, «прогноз/сейчас» стоит справа от раундов. Крестик везде один: `HexRemove`.
- Отменённое компонентом предупреждение остаётся в своём блоке, после действующих, в виде выключенного: приглушённое, зачёркнутое, под ним «Разрешено: <компонент>»; оранжевого края у списка из одних отменённых нет, запись в плане таким предупреждением не помечается (`WarningList`).
- Блок «Использовано» (`UsesBlock`, поле `uses`) стоит в общей части «В этом ходу» после «Взято и сброшено»: кнопка «+ Использовал» над карточками, выбор через `ComponentPicker` ставит первым то, что у игрока готово.
- Груз полёта предлагает и здания планет источника, только если они там есть; прибывшие здания ставятся на планету в блоке высадки.
- Предупреждение стоит в том блоке, где настраивается то, о чём оно говорит: маршрут, высадка, постройка, оплата, жетоны, карта. Блок выбирается по шагу предупреждения (`STEP_PLACES` в `src/ui/feedback/warningPlaces.ts`), поэтому новому правилу правка там не нужна; `PLACES` хранит только исключения, когда один шаг говорит о нескольких блоках. Блок показывает их через `WarningList` с оранжевым краем. Предупреждение, чей блок не на экране, стоит вверху редактора, чтобы не потеряться. Лимиты системы (флот, места на борту) считаются по всему действию и стоят в блоке «Итог действия» в конце тактического редактора, а если есть источники, то и в них; места на борту в активной системе стоят только в итоге: их меняет высадка, которая ниже источников.
- Редактор записи (тактическое действие, карта стратегии, действие компонента, пас, ручная правка) стоит двумя частями под общими заголовками `SectionTitle` (`EditorPart`), того же размера, что заголовки разделов везде: сверху своё («Настройка действия», у карты стратегии её название и способность), ниже общая часть, всегда последняя; её целиком собирает `commonOf` в `PlanScreen`, редактор только ставит её в конец. У хода активного игрока она называется «В этом ходу» и держит блоки в одном порядке: сделки и экспедиция (`TurnActs`), «Взято и сброшено» (`GainsBlock`). У второстепенной способности в ней только «Взято и сброшено»: сделка принадлежит ходу активного игрока (LRR 94.1). У ручной правки она называется «С этой записью» и тоже держит только «Взято и сброшено». У паса только общая часть, у действия из карты (Warfare) только своя. «Итог действия» относится к своей части. Между частями отступ больше, чем между блоками. Любое новое действие из меню сразу открывает свой редактор; действие компонента при этом сразу открывает выбор компонента.
- Один компонент записи выбирается местом `ComponentSlot` (`src/ui/plan/blocks`): пока пусто, это пунктирная кнопка во всю ширину блока, после выбора карточка компонента с крестиком и «Заменить» внутри. Так выбирается компонент действия компонента (заметка стоит ниже) и карта политики.
- Фаза статуса: запись «Жетоны и очки» держит и «Взято и сброшено» с отдельной кнопкой «+ Карта действия» (`lead` у `GainsBlock`, LRR 81.3: какая карта пришла, знает только игрок). Фаза повестки: кнопка «+ Карта политики» добавляет запись (ручная правка в фазе `agenda`, по одной на карту), в её редакторе первой стоит карта политики; закон остаётся в игре и виден в шторке в «Цели и законы», директива ничего не оставляет (LRR 7.3, 7.8), а что изменило решение, вносится числами правки.
- Игроки в выборе (чьё действие, с кем сделка, карты Politics и Trade) называются одинаково: короткое имя фракции, на тесной строке метка из трёх букв (`playerOptions` в `src/ui/primitives/player.tsx`); строка сделки в плане тоже с коротким именем. В сделке «+ Компонент» первыми предлагает обязательства той стороны, которая их получает (`notesOfFirst`): свои возвращаются без поиска.
- Бой тактического действия: строка `.in-card` в редакторе с итогом внутри (как и «Производство»), потери `entry.losses` накликиваются иконками, снимаются после перелёта и до высадки и производства, поэтому влияют на резерв флота и на то, что можно высадить. Юнит из десанта этого действия, потерянный в бою, уходит из `landings` и считается в `losses`; потери тех, кто уже стоял на планете, идут в `groundLosses` и снимаются после высадки. Блок высадки показывает всё после боя. Потери других игроков в действие не входят.
- Маршрут строится одним черновиком: выбор источника только начинает его, а нажатия и штрихи пальцем чередуются в любом порядке. В запись он попадает на активной системе. Пока палец ведёт штрих ближе `EDGE_ZONE` (56 px) к краю видимой области карты (язычки шторок её сужают), карта едет за пальцем, тем быстрее, чем ближе край, до `EDGE_PAN_MAX`, а без плавной анимации с одной скоростью `EDGE_PAN_STEADY` (`src/ui/map/edgePan.ts`, кадры через `panBy` в `usePanZoom`), и системы, приехавшие под палец, входят в маршрут. Палец, вернувшийся на предпоследнюю систему пути, убирает последнюю, и так по одному гексу до первой (`strokeStep` в `src/domain/route.ts`): назад значит только предпоследнюю, давно пройденная система ничего не меняет. Начать его можно в любой системе карты, и без своих кораблей: тогда подсказка говорит, что кораблей в начале маршрута нет, а подсветки нет. Источник, из которого ничего не взято, в записи не остаётся: при возврате из шага перелёта его строка (`Vanishing`) и стрелка гаснут, и только потом он удаляется (`useLeavingSources`: по концу перехода или по таймеру, без плавной анимации сразу); при закрытии редактора его убирает `pruneEmptySources`. Пока он строится, подсказка показывает скорость самого быстрого корабля источника, а подсветка показывает, куда ещё можно долететь. Счёт в `src/domain/movement.ts`: червоточины смежны, дом вне карты (Creuss) смежен только через свою червоточину, гиперпуть соединяет системы только по своим линиям с учётом поворота (у тайлов без данных о линиях, 119-124, соединены все стороны). В астероиды и сверхновую нельзя; в туманность и к чужим кораблям только как в активную систему, и не насквозь; старт из туманности даёт скорость 1; каждый гравитационный разлом даёт +1 за каждый выход или пролёт; две отмеченные подряд несоседние системы (нет общей стороны, червоточины или линии гиперпути) — прыжок: Излом, портал или способность, которую правила здесь не считают; он рисуется пунктиром, стоит один шаг, и системы между ними не проверяются; маршрут можно вывести из активной системы и вернуть в неё; энтропийный шрам на движение не влияет. Технологии не учитываются. Подсветка и предупреждения `speedShort`, `routeBlocked` ничего не запрещают.
- Элемент, который нажимают несколько раз подряд (плитка юнита, «+» и «−», переключатель, «Копия», «+» раунда), не двигается от нажатия: всё, что от него меняется (предупреждение, итог, новая плитка или строка), стоит ниже или правее него, а исчерпанная плитка остаётся на месте погасшей. За этим следит `tests/e2e/steady-controls.spec.ts`; новый повторяемый элемент добавляется в этот тест.
- Элемент управления карточкой (удаление и подобное) стоит внутри карточки, у её правого края, а не сбоку и не вплотную к тексту: класс `.in-card` для кнопки-карточки, как строка источника; строки вроде сохранённых партий и записей плана сами являются карточкой, текст в них занимает свободное место.
- Карта стратегии в сетке: под сеткой показаны свойства основной карты. Первое нажатие на любую карту, и на свою тоже, только открывает её справку; следующие нажатия на неё делают её запасной (при 3-4 игроках второй), основной, снимают выбор. Нажатие вне блока стратегий закрывает справку, возвращает основную карту и начинает счёт заново.
- В режиме «Факт» итоги сверху показывают только то, что есть, без стрелок «А → Б».
- Цвет состояния, три вида: не выбрано без подсветки (край нейтральный); выбрано голубым везде, в том числе вкладки плана, язычки и край открытой шторки, текущий экран меню, лист фракций, действия над картой; зелёный только у выполненного действия (галочка записи и край строки). Золотой только для значений: ресурсы, изменённое число, «пора сделать копию».
- Удалить, изменить, выполнено: тихий значок `.icon-button` (знак 24 px без рамки в поле 44×44). Нажатое или выполненное рисуется шестиугольником за значком без края, с радиальной заливкой, тающей к краям; крестик краснеет только под пальцем или курсором. Шестиугольники меню и действий над картой остаются `.hex-button`.
- Модалы на весь экран размывают фон, это выключается на «Партии» (`localStorage`, `ti4.blur`).
- Блок «Энергосбережение» на «Партии» (`src/ui/screens/EnergySettings.tsx`, `src/ui/common/preferences.ts`): пункты «Перелёты кораблей» (`ti4.flights`, `data-flights`), «Повтор перелётов» (`ti4.flightLoop`), «Плавная анимация» (`ti4.motion`, `data-motion`), «Размытие фона» (`ti4.blur`, `data-blur`) включены по умолчанию и выключаются по одному. «Максимальная экономия» (`ti4.energy`, по умолчанию выключена) стоит в том же ряду: пока она включена, все пункты выключены и заблокированы, их собственный выбор сохраняется и возвращается после неё. На корне всегда то, что действует сейчас (`applyAll`). Код читает анимацию через `reducedMotion()`, перелёты через `playsFlights()`, обе вместе с системной настройкой.
- Повтор перелёта идёт фазами (`useFlightLoop`, `FlightLayer`): откат к состоянию до действия (с жетоном приказа уже на месте), стоянка, взлёт (юниты уходят из систем, строй вырастает в начале маршрута), полёт с подборами (подобранный стек вырастает в строю), долёт до центра целевой системы, высадка (строй тает, юниты появляются). Анимируются только системы действия (`entrySystems`): их планеты, юниты и метки рисуются порталом в слой `hexmap-lift` поверх карты, остальные тайлы получают `tile-quiet` и меняются мгновенно. Смена числа у стека — это уход старого значка и появление нового (`TokenLayer`). Летящие юниты рисуются в своём слое `hexmap-overlay` поверх карты. Кадры жеста и подлёта камеры пишут трансформацию прямо в DOM (`onFrame` в `usePanZoom`), React узнаёт вид только в конце.
- Перелёт в открытых деталях повторяется, только если ему есть что показать (`flies`). Между повторами карта стоит в состоянии сразу после действия (`stateAfterEntry`), чтобы последующие записи плана не мигали.
- Кнопка экспорта с иконкой (`ExportReminder`) стоит внизу колонки меню и просит постоянное хранение; когда нужна новая копия, она отмечена золотым. Время последней файловой копии лежит в `localStorage` (`ti4.lastExportAt`). Отметка появляется, если копии не было никогда, если она старше недели при постоянном хранении или старше суток без него. Экспорт её снимает.

- Битое сохранение ничего не ломает: оно стоит в списке с сообщением «Сохранение не удалось загрузить», его можно выгрузить как есть или удалить с подтверждением, само оно не удаляется никогда; падение отрисовки открытой партии возвращает на «Партию» с тем же сообщением (`src/storage/db.ts`, `src/ui/common/ErrorBoundary.tsx`).

## Ссылка на партию

Query-параметры (`src/domain/shareLink.ts`): `name` (имя сохранения), `map` (строка Milty), `factions` по местам с первого, коротким кодом из трёх hex-цифр (`factionCode`, хеш id; `-` значит пусто, старые ссылки с id тоже читаются), `me` (своё место), `exp` (`pok,te`, `base` значит без дополнений), `layout`. При запуске: сохранения с таким именем нет, партия создаётся и открывается (без своей фракции ждёт в черновике); есть и не расходится со ссылкой, открывается; расходится, окно `ShareConflict` предлагает новую партию под другим именем или игнорировать ссылку. Сохранение ссылка не меняет никогда, то, что она не упоминает, расхождением не считается. Без `name` ссылка только заполняет черновик. Пока партия открыта, адрес всегда содержит её параметры (`App`, без записей в истории), поэтому его можно просто скопировать; без открытой партии адрес чистый. Планы в ссылку не входят; кнопка «Скопировать ссылку» на «Партии» собирает её.

## Действия соперников

В план можно внести ожидаемое действие соперника: у записи есть `owner`. Соперник считается тем же кодом, что и я: `gameAs` показывает партию его глазами, а `state.rivals[id]` хранит его состояние, начиная с того, что стоит на карте. Редакторы и большой гекс получают `gameAs`, стрелки и жетоны окрашены цветом игрока. Номер тактического действия значит круг этого игрока: у каждого счёт свой, с единицы. Действие без жетона по карте Warfare считается в том же ряду: его номер стоит у стрелки и в строке карты. Строка соперника сдвинута вправо и с оттенком его цвета, а левая граница у неё значит то же, что у моих: выполнено или предупреждение. На мои итоги действия соперника не влияют, кроме контроля планеты при его высадке. После старта партии нельзя менять имя, добавлять соперников и пересаживать игроков. При старте партии `placeStartUnits` ставит стартовые юниты соперников на их места: корабли в космос системы, наземные войска и космопорт на первую планету дома (LRR 43.1; `splitStartUnits`, у меня то же в `initialState`), поэтому начальный перелёт не оставляет «груза» в космосе. Выбор стартовой технологии («Выбор при подготовке») делается на листе игроков нажатием на технологию (`FactionCard`, `chosen`/`onChoose`).

## Правила домена

- Предупреждения ничего не запрещают: способности и технологии могут менять правила. Ручная правка с подписью остаётся для того, что правила приложения не покрывают.
- Повтор применяет то, что введено, а не то, что помещается в лимит: взятое в перелёт сверх стоящего в источнике летит, прибывает и считается в грузе, местах на борту и резерве флота (`moveUnits`, предупреждение `unitsMissing`), высаженное сверх прибывшего высаживается и берёт планету (`landUnits`, `landingOverLimit`); источник при этом только пустеет, ниже нуля не уходит. Анимация перелёта показывает то же (`flightRoutes`, `flies`). За этим следит `tests/e2e/over-limit.spec.ts`.
- Компоненты (`src/domain/components.ts`): плоский каталог всех видов поверх пакетов, id `'<вид>:<id источника>'`. Владение (`Holdings` в `GameState`, `src/domain/holdings.ts`) не хранится, а получается повтором: исходное в `Game.start`, дальше `gains`/`spends` записи, `effects.researched` карты Technology, `componentId` компонентного действия, `scored` фазы статуса. Улучшение юнита — это технология во владении; отдельного списка улучшений нет.
- Поиск компонентов один: `searchComponents` в `src/domain/componentSearch.ts` (нечёткий поиск в `src/domain/fuzzy.ts`), его зовут и шторка, и окно выбора через одну строку `ComponentSearchField`. Каждое слово запроса должно найтись в компоненте (с опечатками, «ё» как «е», другой формой слова, в другой раскладке): в названии, в виде (технология, агент, закон…), в свойствах (цвет технологии и улучшаемый юнит, этап цели, тип карты политики и кого она выбирает, фаза, черта карты исследования, фракция, дополнение) или в тексте (как показан, английский оригинал `pack.originalTexts`, окно карты действия). Порядок: название, вид, свойства, текст. Слова вида и свойств стоят в домене сразу на двух языках (`KIND_TERMS`, `TECH_TERMS` и другие), от языка интерфейса они не зависят; `useComponentSearch.test.ts` сверяет их с подписями i18n. Русское слово читается и по звучанию: «саботаж» находит Sabotage. Индекс строится один раз на пакет (пакет свой у каждого языка текстов); скорость меряет `componentSearch.bench.ts`.
- Обязательство во владении — карта одного игрока: id экземпляра `promissory:<id>@<игрок>` (`me` или id соперника; `noteBase`, `noteAddress`, `noteId` в `components.ts`, `noteOwner`, `noteText`, `noteCards` в `holdings.ts`), каталог знает его по базовому id, а в сделке и при розыгрыше оно ходит как есть, с адресом. При создании партии, добавлении игрока и выборе фракции каждому раздаются его общие обязательства (четыре в базе, Alliance с Prophecy of Kings) и обязательства его фракции; удаление игрока убирает их из стартов и записей. Своё обязательство сыграть нельзя (`ownPromissory`, 69.2); чужое, в тексте которого «Then, return this card to…», после розыгрыша возвращается владельцу (69.3). В тексте карты `<color>` при показе заменяется именем владельца (`noteMark` в `src/ui/components`).
- Эффекты (`src/domain/effects/`): у каждого компонента каталога запись в реестре с классом. `passive` применяется сам через `applied(pack, holderOf(game, state), точка, база, контекст)` — шаг расчёта не знает компонентов по имени; истощённая карта пассивно действует по-прежнему (LRR 34.4.1). `play` применяется, когда компонент сыгран записью. `hint` только показывается в блоке своего шага (`hintsAt`, `StepHints`): всё боевое и реакции. Эффект компонента лежит в своём файле `src/domain/effects/components/<вид>/<id>.ts` (экспорт `id` и `effect`, путь даёт `fileOf`), рядом его тесты `<id>.test.ts` и тест интерфейса `<id>.ui.test.tsx`; реестр собирает файлы сам (`import.meta.glob`), общие файлы при этом не правятся. Улучшения юнитов по-прежнему генерируются. Контрактный тест `src/domain/effects/contract.test.ts` следит за полнотой. Как писать эффект и его тесты: [docs/phase4/component-effects.md](docs/phase4/component-effects.md).
- Что в силе у игрока без розыгрыша (`inForce`, `holderOf` в `registry.ts`): технологии, реликвии, обязательства и лидеры во владении, способности и мех листа его фракции, прорыв, когда он получен, легендарные планеты под его контролем, законы в игре. Способность флагмана в каталог не входит.
- Компонент может отменить проверку (`waive` в эффекте, `src/domain/effects/waivers.ts`): предупреждение создаётся как всегда и остаётся в списке, но получает `waivedBy` с id компонентов. Отмена `passive` действует, пока компонент в силе; отмена `play` и `hint` — в записи, которая называет компонент (компонентное действие, `spends`, `uses`), а с `lasts: 'round'` до конца раунда. Отмена не меняет чисел: изменение предела — это `modify`. Всё, что спрашивает «есть ли у записи нарушение», спрашивает `standing(warnings)`. Применяется в одном месте, после сбора предупреждений записи в `timeline.ts`.
- Поле `uses` записи: компоненты, применённые в этом ходу помимо самого действия и не сброшенные (истощённый агент или технология). Каждый разыгрывается как в компонентном действии: истощается, убирается или сбрасывается, а отсутствующий или истощённый даёт предупреждение.
- Здания на борту: `moves[].structures` берёт здания с планеты или из космоса системы, `landings[].structures` ставит их на планету в конце действия, `GameState.afloat` хранит здания в космосе. Правила это запрещают (85.3, код `structureAboard`), здание всё равно летит.
- Повтор плана идёт одним проходом (`src/domain/replay/timeline.ts`): кадр «до» и «после» на каждую запись, при правке пересчёт с изменённого раунда. `src/ui` план не проигрывает, а спрашивает `timelineOf` из `src/state/projection.ts` (контрактный тест).
- Сохранения: формат `ti4-planner/2`, миграций нет; сохранение прежней версии стоит в списке как непрочитанное, его можно выгрузить или удалить.
- Канал нарушений один. Предупреждение (`Warning`) создаёт только домен, через `violation` из `src/domain/rules/registry.ts`; оно несёт правило (`rule`), шаг (`step`) и место (`place`: запись, источник, планета). Реестр `RULES` даёт каждому коду пункты LRR и шаг, на котором он проверяется. Новый код — один файл `src/domain/rules/codes/<код>.ts` с `defineCode`: пункты LRR, шаг и тексты ru и en; реестр и интерфейс берут его сами, тест правила или компонента обязателен. Прежние коды остаются в `WARNING_CODES` (`types.ts`) и `RULES`. Контрактные тесты `src/domain/rules/contract.test.ts` требуют, чтобы каждый код был в реестре и в тесте правила, у каждого шага был блок, а `src/ui` предупреждений не создавал.
- Стратегия в меню одна: сначала карта (по умолчанию моя ещё не сыгранная в этом раунде, иначе никакой), затем её основная или второстепенная способность. Основная бесплатна на моей карте и стоит жетон на чужой. `forToken` выводится из карт раунда (`primaryForToken`): пока карта раунда выбрана, решает она, флаг записи учитывается, только когда карт нет; `withForTokenOfRound` подгоняет сохранённые записи. Мои карты зависят от числа игроков (`heldCards`): при 5 и больше только основная. Повтор своей карты за раунд предупреждает (`primaryRepeated`). Второстепенная стоит жетон, кроме Leadership. Карты соперников не планируются, поэтому их основная бесплатна.
- Блок «Взято и сброшено» записи (`GainsBlock`, поля `gains` и `spends`) — только то, что приходит из колоды или запаса и уходит в сброс или из игры; передача другому игроку — сделка. «Сбросил» предлагает лишь то, что владелец записи держит до неё (`losable`), «Взял» — весь каталог. Выбор компонента (`ComponentPicker`: `ids`, `owned`, `prefer`) ничего не запрещает: компонентное действие ставит первым то, что у игрока готово (`readyToPlay`), остальное помечено.
- Здания принадлежат тому, кто контролирует планету: состояние игрока хранит только свои, а захват планеты другим игроком их уничтожает (`src/domain/replay/structures.ts`).
- Дополнения выбираются независимо: Thunder's Edge требует базовую игру, но не Prophecy of Kings.
- Раскладки карты по правилам PoK, у каждого числа игроков две (`LAYOUT_CHOICES` в `src/domain/layouts.ts`): на 3-5 обычная и с гиперпутями (на 3 и 4 гиперпути Milty), на 6 обычная и Большая галактика, на 7 с гиперпутями и альтернативные гиперпути, на 8 обычная и альтернативные. По умолчанию раскладка правил: гиперпути на 5 и 7. Шаблоны 6-8 игроков переписаны вручную с диаграмм правил (`RULEBOOK_LAYOUTS` в `scripts/build-data.ts`); смена раскладки переносит дома на места новой. Карты на 7 без гиперпутей в правилах нет.
- Набор стратегических карт зависит от дополнений. Thunder's Edge заменяет Construction и Warfare.
- Стрелки на карте используются только для перемещения в тактическом действии.
- Лидеры и мехи существуют только с Prophecy of Kings, даже у фракций Thunder's Edge (правила TE). Агенты открыты с начала партии (`startForFaction`, LRR 51.4). Состояние лидера на начало плана выбирается в шторке компонентов сегментами по его типу: агент «закрыт, открыт, истощён», командир «закрыт, открыт», герой «закрыт, открыт, убран»; то, что с лидером сделал план, там только показано. Thunder's Edge заменяет часть карт: у Jol-Nar Ta Zern на Agnlan Oln; что на что, задано в `scripts/build-data.ts`. Каждый такой компонент подписан дополнением.
- Системы открытого Излома лежат в `game.fracture.tiles` под обычными ключами слотов, поэтому ходы, расчёт и большой гекс работают с ними как с картой. Они не смежны с тайлами карты рядом: такой шаг маршрута рисуется разрывом.

## Данные и язык

- Игровые данные берутся только из публичных источников и хранятся как пакеты с указанием происхождения. Источники и правила сборки описаны в спецификации.
- Числа из прототипов частично заполнены по памяти, не переноси их в приложение.
- Не копируй арт из игры и источников: лицензия AsyncTI4 его исключает, а у KeeganW/ti4 лицензии нет. Оригинальные тексты компонентов дословные, на английском: их пишет только сборщик из источника в `src/data/texts/<pack>.json`, вручную они не набираются и не правятся. При русском интерфейсе показываются их переводы из `src/data/texts/<pack>.ru.json` (термины по русскому справочнику и глоссариям `docs/phase3/ru-glossary-*.md`, названия остаются английскими), их проверяет `npm run lint:terms`; при английском интерфейсе показан оригинал. Язык текстов следует за языком интерфейса (`setTextLanguage` в `src/data/loadPack.ts`); экран берёт пакет через `usePack` (`src/ui/common/usePack.ts`), чтобы смена языка пересобрала всё, что построено на пакет.
- Интерфейс идёт через i18n: русский и английский, с выбором языка. Игровые названия остаются на английском. Термины игры берутся из официальных правил: английские по Rules Reference, русские по Hobby World (жетон приказа, тактический и стратегический резерв, резерв флота, база, наземные войска, второстепенная способность, места на борту, значение полёта); следит `npm run lint:terms`. Если полный термин не помещается в кнопку, перестрой фразу, а не сокращай термин. Исключение: commodities по-русски «Продукция», trade goods «товары».
